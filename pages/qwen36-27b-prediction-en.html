🧠 Architecture: Why It Improves

To understand the performance jumps, you need to look under the hood. Qwen3.5 and Qwen3.6 share the same architectural family, but with crucial differences.

Key concept: Gated DeltaNet + Gated Attention

Both generations use a revolutionary hybrid architecture combining the best of two worlds: DeltaNet (linear O(n) attention, ultra-efficient) and Traditional Attention (softmax O(n²), expressive but costly). The "gating" allows the model to learn when to use each dynamically.

What is DeltaNet?

DeltaNet is an linear attention architecture with state memory. Instead of computing attention over all context tokens (O(n²)), it maintains a fixed-size compressed memory state — similar to how an RNN condenses history into a hidden state, but with attention capability.

  • Traditional softmax attention: O(n²) — all tokens compare with all. Precise but slow and memory-expensive
  • DeltaNet: O(n) — each token processed once, updating a compact state. Fast and efficient, but context capacity limited by memory size
  • Gated DeltaNet: uses a gate that decides how much weight to give the DeltaNet path vs the traditional attention path per token — the best of both worlds

Layer Layout: the 3:1 Block

Instead of alternating layers equally, the dense models use a specific pattern of 3 DeltaNet layers per 1 Attention layer, repeated 16 times = 64 total layers:

Qwen3.5/3.6-27B (Dense) — Per-block Layout
Gated DeltaNet → FFN
Gated DeltaNet → FFN
Gated DeltaNet → FFN
↓
Gated Attention → FFN
↻ repeat 16 times = 64 layers

75% of layers are DeltaNet (efficient), 25% are Attention (expressive). The gate learns dynamically when to trust each path.

⚡ The reveal: 3.5-27B and 3.6-27B share the SAME architecture

Same model, same skeleton, different brain.

Comparing the HuggingFace cards, Qwen3.5-27B and Qwen3.6-27B are architecturally identical: same layers (64), same hidden dim (5120), same heads (48/16 DeltaNet, 24/4 GQA), same 16×(3Δ+1A) layout, same FFN (17,408). The performance jump does NOT come from an architectural change.

So why does it improve so much?

If the architecture is identical, the +17.7 points on Terminal-Bench, the +2.3 on GPQA, and the rest of the improvements come from:

Dense vs MoE: why does the dense 27B compete with much larger MoEs?

This is the key question. The Qwen3.6-27B dense competes head-on with the Qwen3.5-397B-A17B (which has 14.7× more total parameters):

Dense model advantages:
  • ✅ More layers (64 vs 48/40): Greater depth = more chained reasoning capacity
  • ✅ Larger DeltaNet head count (48 vs 32): More context compression capacity in the efficient path
  • ✅ No routing overhead: No loss from poor expert selection
  • ✅ Full activation: All 27B params work on every token (vs only 3B in the 35B MoE)
  • ✅ No expert load balancing: No classic MoE problem of underutilized experts
MoE advantages:
  • ✅ Specialization: Different experts for different task types (code, math, language)
  • ✅ Inference efficiency: Only 3B active params = faster on optimized hardware
  • ✅ Scalability: Add experts without increasing inference cost

But the Qwen3.6 35B-A3B MoE is extremely lightweight (only 3B active) — that limits its capacity. The 397B-A17B with 17B active params is much more competitive.

MTP: Multi-Token Prediction

Both generations include native Multi-Token Prediction (MTP) — the model predicts multiple tokens at once, not just the next one:

MTP: The model predicts several steps ahead
Token N → predicts N+1, N+2, N+3
↓

If the speculative prediction is accepted, steps are skipped. In vLLM: +30-50% speed. In llama.cpp: no native support yet.

Vision Encoder: native multimodal

Unlike text-only models, Qwen3.5/3.6-27B includes an integrated Vision Encoder with early fusion: images are processed as tokens from the first layers, not as a later add-on. This gives impressive vision capabilities:

Architectural lesson:

For a consumer-size model (~27B) that fits on consumer GPUs, the best strategy is dense + many layers (64) + more DeltaNet heads (48). The ultra-light MoE (3B active) is too limited; the heavy MoE (17B active) requires datacenter infrastructure. Dense is the sweet spot for consumer hardware.

The 3.5→3.6 improvement comes from where you train (massive RL in real environments), not how you build it (architecture stays the same). Qwen is betting on "more RL, better data" rather than changing the model skeleton.

⚠️ Benchmarks Aren't Everything

Warning: Benchmarks show direct competition, but real-world production experience tells a different story.

1. Scaffold Advantage

Qwen's coding benchmarks use their internal agent scaffold (bash + file-edit tools optimized for the model). Claude uses Claude Code with its own tool system. They are different setups.

2. Where Local Models Shine

Local models like Qwen3.6-27B excel at:
  • ✅ Getting insights and feedback on codebases
  • ✅ Reasoning where they outperform benchmarks (GPQA: 87.8, SkillsBench: 48.2)
  • ✅ Total privacy — data never leaves your machine
  • ✅ Zero cost after hardware
  • ✅ Customization — fine-tuning for your domain
